# Security Policy

## Supported versions

The latest published release of Music is the primary target for security fixes. Please report a vulnerability even if you found it in an older version; include the affected version so we can check whether the latest release is affected.

## Reporting a vulnerability

Please report vulnerabilities in Music privately through the repository's [Security Advisories](https://github.com/indradprasetya/yt-music-webkit/security/advisories) page by selecting **Report a vulnerability**, if that option is available.

If private reporting is unavailable, [open an issue](https://github.com/indradprasetya/yt-music-webkit/issues/new) asking for a private security contact. Do not include the vulnerability details, exploit steps, or sensitive data in the public issue. The maintainer can then arrange a private reporting channel.

When reporting privately, include the affected app version, macOS version, potential impact, and steps to reproduce the issue. Redact credentials, personal information, and other secrets from any logs or screenshots.

This policy covers vulnerabilities in the Music app and its distribution or update process. If the issue is solely in YouTube Music or another Google service, report it to Google instead.

Please allow time for investigation and a coordinated fix before publicly disclosing a vulnerability.
